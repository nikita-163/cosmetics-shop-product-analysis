# Продуктовый анализ магазина косметики

## О проекте

В рамках этого проекта анализируются событийные данные интернет-магазина косметики: на каком этапе воронки 
теряются пользователи, как удерживаются разные когорты и что из этого
следует для продуктовых гипотез. 

## Бизнес-задачи

В рамках проекта необходимо ответить на следующие вопросы:

- где воронка: просмотр -> корзина -> покупка теряет больше всего пользователей?
- как удерживаются пользователи разных недельных когорт?
- какая доля покупателей возвращается за повторной покупкой и через сколько дней?
- где концентрируется выручка?
- какие метрики рассчитываются в проекте?
- какие гипотезы следуют из найденных наблюдений и проблем?

## Цели проекта

- Провести EDA и очистку данных в pandas.
- Создать базу данных для хранения событий.
- Загрузить очищенные данные в PostgreSQL.
- Рассчитать продуктовые метрики средствами SQL.
- Собрать дашборд в DataLens и оформить отчёт

## Источники данных

Датасет REES46 «eCommerce Events History in Cosmetics Shop» (Kaggle): события интернет-магазина косметики (просмотр, корзина, удаление из корзины, покупка) с временем события, пользователем, сессией, товаром, категорией, брендом и ценой. Файлы разбиты по месяцам.

Источник: **REES46 Marketing Platform** 
Cсылка на страницу датасета на Kaggle: https://www.kaggle.com/datasets/mkechinov/ecommerce-events-history-in-cosmetics-shop?select=2019-Nov.csv

## Ограничения

- В данных нет `order_id` и количества товара, поэтому заказ определяется по покупкам одной сессии, а выручка считается по цене в событии покупки.
- Когорты составляем с первого дня выбранных данных, поэтому в первую когорту попадают и старые клиенты.
- Магазин и география пользователей неизвестны, время хранится в UTC.
