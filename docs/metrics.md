# Метрики, которые будем считать

## Файл фиксирует:
1. какие метрики считаем;
2. для чего;
3. какие события или действия считаем;
4. в чём измеряем подсчёт;
5. за какой период считаем;
6. ожидаемый результат.

## 0. Общие правила расчёта

- **Время.** Всё в UTC. Неделя: с понедельника по воскресенье, месяц: календарный. Данные: с 1 окт 2019 по 29 фев 2020. Месяцы полные, а первая (1-6 окт) и последняя (24-29 фев) недели неполные (6 дней из 7): в недельных таблицах они помечаются флагом "is_full_week".
- **Заказ.** В данных нет "order_id", поэтому заказ = пара ("user_session", "user_id") хотя бы с одной покупкой ("purchase") без дубля и с ценой не "NULL".
- **Деньги** (GMV, покупки и заказы с известной ценой, AOV, ARPPU) считаем только по строкам без дублей и с ценой не "NULL". **Поведение** (воронка, активность, retention) считаем по всем событиям, включая дубли и покупки с ценой "NULL".
- **К какому периоду относится.** Заказ и его GMV относятся к периоду первой покупки с ценой в сессии ("first_order_time"). Сессия в Session conversion и Abandonment относится к периоду начала сессии ("session_start"). Пользователь в месячной воронке засчитывается по событиям внутри этого месяца.

## 1. Воронка и конверсия

Шаги: **view → cart → purchase**. 

Шаг засчитывается, если у пользователя есть событие нужного типа за период. Пользователи шага N учитываются только среди прошедших шаг N−1. Покупатели без "view" за период в воронку не попадают.

| Метрика | Цель подсчёта | События / действия | Единица измерения | Период | Ожидаемый результат |
|---|---|---|---|---|---|
| Пользователи на шагах воронки | Увидеть, на каком шаге теряются больше всего пользователей | Уникальные пользователи с >= 1 событием "view"; из них с "cart"; из них с "purchase" | Число уникальных пользователей и доля в % | Весь период и по месяцам | Число и доля пользователей на каждом шаге |
| Step conversion rate | Найти самый слабый этап воронки | "view → cart" и "cart → purchase": уникальные пользователи шага N / уникальные пользователи шага N−1 | Доля в % | Весь период и по месяцам | Доли двух конверсий |
| Conversion rate | Оценить общую эффективность пути до покупки | Уникальные пользователи с "view", "cart" и "purchase" / уникальные пользователи с "view" | Доля в % | Весь период и по месяцам | Доля пользователей, дошедших до покупки |
| Session conversion rate | Сравнить с воронкой по пользователям: один человек может прийти за покупкой несколько раз | Уникальные сессии с "view", "cart" и "purchase" / уникальные сессии с "view" | Доля в % | Весь период и по месяцам | Доля покупок по уникальным сессиям |
| Abandonment rate | Посмотреть, сколько корзин не оформляются | 1 − (уникальные сессии с "cart" и "purchase" / уникальные сессии с "cart") | Доля в % | Весь период и по месяцам | Доля брошенных корзин |
| Доля удалений из корзины | Оценить, как часто товар убирают из корзины | Уникальные пользователи с "cart" и "remove_from_cart" / уникальные пользователи с "cart" | Доля в % | Весь период и по месяцам | Доля удалений из корзины |

Примечания к воронке:
- Session conversion: сессия с покупкой, но без "view", не попадает ни в числитель, ни в знаменатель.
- Abandonment rate даёт оценку сверху: корзина, оформленная в другой сессии, считается брошенной.
- Доля удалений: "remove_from_cart" не обязательно следует из "cart" того же периода, поэтому в знаменателе берём только пользователей с "cart".

## 2. Метрики активности

Активный пользователь: уникальный пользователь ("user_id") хотя бы с одним событием любого типа ("view", "cart", "remove_from_cart", "purchase") за период.

| Метрика | Цель подсчёта | События / действия | Единица измерения | Период | Ожидаемый результат |
|---|---|---|---|---|---|
| DAU | Оценить ежедневную аудиторию, найти пики и провалы | Уникальные активные пользователи за календарный день | Число уникальных активных пользователей | По дням за весь период | Число ежедневных уникальных активных пользователей |
| WAU | Сгладить дневные колебания и посмотреть недельную аудиторию | Уникальные активные пользователи за неделю | Число уникальных активных пользователей | По неделям за весь период | Число недельных уникальных активных пользователей |
| MAU | Оценить месячную аудиторию | Уникальные активные пользователи за календарный месяц | Число уникальных активных пользователей | По месяцам | Число уникальных активных пользователей по каждому месяцу |
| Stickiness | Понять, какая доля месячной аудитории заходит в среднем каждый день | Среднее DAU за месяц / MAU того же месяца | Доля в % | По месяцам | Доля по месяцам |

Примечание: WAU и MAU считаем напрямую как число уникальных пользователей за период, а не суммой DAU (пользователи повторяются по дням). Среднее DAU берём по всем календарным дням месяца.

## 3. Когорты и retention

| Метрика | Цель подсчёта | События / действия | Единица измерения | Период | Ожидаемый результат |
|---|---|---|---|---|---|
| Когорты | Посмотреть, как меняется поведение пользователей в разрезе событий | Уникальные пользователи с событием любого типа на неделе 1, 2, 3 ... | Число уникальных пользователей в каждой когорте | По неделям за весь период данных | Количество когорт |
| Retention недели N | Оценить долю возвращающихся пользователей | Любое событие уникального пользователя в неделе "когорта + N" | Доля в % от размера когорты | От первой до последней когорты | Доля возвращающихся пользователей по каждой когорте |
| Purchase retention | Увидеть, возвращаются ли пользователи именно за покупками | Событие "purchase" уникального пользователя в неделе "когорта + N" | Доля в % от размера когорты | От первой до последней когорты | Доля пользователей, возвращающихся за покупками |
| Repeat purchase rate | Оценить долю пользователей, которые возвращаются за повторной покупкой | Уникальные пользователи с уникальными сессиями с покупкой >= 2 с известной ценой / уникальные пользователи хотя бы с одной покупкой с известной ценой | Доля в % | Весь период и по когортам | Доля за весь период и в разбивке по когортам |
| Repeat purchase rate за 30 дней | Сравнить когорты без искажения: у поздних когорт было меньше времени вернуться | Пользователи, у которых второй заказ был не позже чем через 30 дней после первого / пользователи с >= 1 заказом, у которых первый заказ не позже 30 января 2020 (после него до конца данных остаётся 30 дней) | Доля в % | По когортам | Сопоставимая доля повторных покупок по когортам |
| Время до повторной покупки | Понять, через сколько времени пользователи возвращаются за повторной покупкой | Время между первой уникальной сессии c покупкой и второй уникальной сессии с покупкой у покупателей с >= 2 заказами | Дни | За весь период и по месяцам | Временной показатель |

Примечания к когортам и retention:
- Недели "когорта + N", которые неполные или выходят за период данных, помечаются и не интерпретируются. Неделя 0 по определению равна 100%.
- Первая когорта неполная и включает старых клиентов, поэтому "первый" заказ в данных не обязательно первый в жизни пользователя.
- Месяц для времени до повторной покупки определяется по второму заказу (видно, когда повторы происходят реально). Если считать по месяцу первого заказа, у поздних месяцев интервалы искусственно короче из-за обрыва данных 29 февраля.

## 5. North Star Metric

Критерии выбора: метрика отражает ценность для пользователя и бизнеса одновременно, на нее можно влиять продуктовыми изменениями и она подходит под бизнес модель.

За NSM можно взять GMV в неделю. Неполные первая и последняя недели помечаются флагом "is_full_week" и в тренде NSM не интерпретируются. 
Берём метрику, так как

1. Пользователь получает ценность, когда покупает то, что искал;
2. GMV отражает оборот и напрямую влияет на выручку бизнеса;
3. Можно разложить на дерево метрик и влиять продуктовыми изменениями.

Изначально, пока не знаем распределения времени между покупками, будем отслеживать GMV в неделю.

Diagnostics metrics
1. WAU;
2. Conversion rate;
3. Step conversion rate;
4. Среднее количество заказов на активного пользователя;
5. AOV;
6. ARPPU.

Guardrails metrics
1. Purchase retention и Repeat purchase rate. GMV растёт, а люди перестают возвращаться (разовые покупки, акции);
2. Количество покупок с известной ценой и количество заказов с известной ценой. GMV растёт от повышения цен, а покупок и заказов становится меньше;
3. Session conversion rate и abandonment rate. Путь до покупки ухудшается, а GMV держится на постоянных покупателях.

## 6. Ограничения метрик

1. Нет "order_id" и количества товара: заказ определяется по сессии, в GMV одно событие = одна единица, валюта неизвестна.
2. 272 сессии содержат больше одного "user_id": они делятся по пользователям, поэтому заказов может быть чуть больше, чем уникальных "user_session" с покупкой.
3. 4 598 событий (0,02%) без "user_session" не попадают в метрики по сессиям, но учитываются в метриках по пользователям. Покупок без сессии в данных нет, поэтому GMV не теряется.
4. Воронка строгая: покупатели без "view" за период в неё не попадают.
5. Abandonment rate завышен: корзина, оформленная в другой сессии, считается брошенной.
6. Первая когорта включает старых клиентов, "первый" заказ в данных не всегда первый в жизни пользователя.
7. Поздние когорты имели меньше времени на повторную покупку: сравнивать их по Repeat purchase rate за 30 дней.
8. GMV сессии относится к времени первого заказа с ценой. На границе недели или месяца возможен небольшой сдвиг; проверяем сверкой с расчётом из "stg.events" по "event_time".
9. Первая и последняя недели неполные (6 дней из 7); месяцы полные.
